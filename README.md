# Новостной портал — Клиент-серверное веб-приложение (Толстый клиент / SPA)

Современное клиент-серверное веб-приложение, реализованное по архитектуре **«Толстый клиент» (Single Page Application / CSR)** с бэкендом на **FastAPI**, базой данных **SQLite** и аутентификацией на **JWT-токенах**.

Весь пользовательский интерфейс (UI) генерируется **на стороне клиента** динамически через JavaScript, а сервер функционирует как производительный REST API.

---

## 🏗 Архитектурные требования и их реализация

| Требование задания | Реализация в проекте |
|---|---|
| **1. Аутентификация пользователя** | **JWT (JSON Web Tokens)**: при входе сервер выдает токен, клиент сохраняет его в `localStorage` и прикрепляет к заголовку `Authorization: Bearer <token>`. Реализовано разграничение прав (`admin` / `user`), хеширование паролей через `bcrypt`, регистрация и модерация. |
| **2. Толстый клиент (Rich Client)** | Клиентская часть берет на себя логику приложения, локальное состояние, валидацию форм и клиентскую маршрутизацию (Hash Routing) без перезагрузки страниц браузера. |
| **3. Сайт** | Полноценный новостной портал с главной страницей, каталогом публикаций, поиском, детальной статьей, комментариями и административной панелью управления. |
| **4. Генерация UI на стороне клиента** | **Client-Side Rendering (CSR)** на чистом JavaScript (ES6): модуль `static/js/ui.js` динамически генерирует все DOM-элементы, карточки, таблицы, модальные окна, фильтры и интерактивные графики. |
| **5. База данных** | Реляционная база данных **SQLite** (`data/news_portal.db`) с таблицами `news`, `categories`, `users`, `comments`, `views`, `searches`, индексами и каскадным удалением связей. |
| **6. Обращение на сервер** | Модуль `static/js/api.js` отправляет асинхронные `fetch()`-запросы к REST API сервера (`/api/...`), обмениваясь структурированными данными в формате **JSON** и обрабатывая коды ответов. |

## 💻 Клиентская архитектура (Толстый клиент)

Клиент работает как одностраничное приложение (SPA):
1. **`api.js`**:
   - Автоматически прикрепляет заголовок `Authorization: Bearer <token>` ко всем защищенным запросам.
   - Обрабатывает ответы сервера, парсит JSON и перехватывает ошибки.
   - Сохраняет сессию в `localStorage`.
2. **`router.js`**:
   - Перехватывает событие смены хэша в строке браузера (`hashchange`).
   - Поддерживает разделы: `#home`, `#news`, `#news/:id`, `#login`, `#register`, `#admin`, `#admin/news`, `#admin/categories`, `#admin/comments`, `#admin/users`, `#admin/statistics`.
   - Защищает панель администратора: при отсутствии прав администратора перенаправляет на `#login`.
3. **`ui.js`**:
   - Не получает готовый HTML от сервера: получает сырые данные в формате JSON и динамически создает узлы DOM в контейнере `#app-content`.
   - Генерирует интерактивные карточки новостей, списки категорий, пагинацию, модальные окна редактирования и удаления.
   - Строит визуальные интерактивные графики **Chart.js** на элементе `<canvas>` по данным аналитики.

## 📡 Серверный REST API

- **Аутентификация:**
  - `POST /api/auth/login` — вход по логину и паролю, возвращает JWT токен.
  - `POST /api/auth/register` — регистрация нового пользователя.
  - `GET /api/auth/me` — получение профиля текущего пользователя по JWT.
- **Новости и категории:**
  - `GET /api/news/home` — горячие и последние новости, категории с количеством.
  - `GET /api/news` — каталог с фильтрацией по категории, дате, поисковой фразе и пагинацией.
  - `GET /api/news/{id}` — полная новость со счетчиком просмотров и комментариями.
  - `POST /api/news/{id}/comments` — добавление комментария авторизованным пользователем.
  - `GET /api/categories` — список всех категорий.
- **Панель администратора (требуется JWT с ролью `admin`):**
  - `GET /api/admin/dashboard` — счетчики и сводка.
  - `GET`, `POST`, `PUT`, `DELETE /api/admin/news` — CRUD новостей с загрузкой обложек.
  - `GET`, `POST`, `PUT`, `DELETE /api/admin/categories` — управление категориями.
  - `GET`, `PUT`, `DELETE /api/admin/comments` — модерация комментариев.
  - `GET /api/admin/users`, `POST /api/admin/users/{id}/action` — управление статусами пользователей (подтверждение, блокировка, назначение прав).
  - `GET /api/admin/statistics` — данные просмотров и поисковых запросов для графиков.
